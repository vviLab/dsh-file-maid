# 文件与目录命名规则 · v1.0

> **定位**：规定工作区内目录与文件的命名形态、字符集合与版本约定，供新建、定名与复核时直接对照。
>
> **适用范围**：工作区内业务目录、业务文件与归档副本的名称。
>
> **排除范围**：文件内容格式、存放位置选择、权限与保留策略不在本文件范围。

## 1 总则

命名规则只约束「叫什么名字」，不约束内容与存放位置。

- 命名对象分三类：目录名、文件名、归档副本名。
- 名称一次生成即应合规，不得先落盘后改名。
- 名称不做自动清洗，不合规的名称不得使用，须先修正名称再落盘。
- 以点开头的名称（`.`、`..` 除外）属系统约定名，不参与本规则的形态判定。
- 同一目录下不得存在两个折叠后相同的名称，判定方式见 §4 重名项。

## 2 目录命名

目录名由两位编号、连字符与描述段构成，编号位承担排序与号段保留约定。

**文法**：`^[0-9]{2}-<描述>$`，整名匹配，不允许多余字符。

| 项 | 规定 |
| --- | --- |
| 结构 | 两位十进制编号 + 半角连字符 `-` + 描述段，编号与连字符之间无空格 |
| 编号位 | 固定两位十进制 |
| 编号选取 | 取十位递增序列中的最小未占用编号 `10 → 20 → … → 90`；十位用尽后按 `11`–`98` 递增补位；无可用编号即停止并报告 |
| 保留号 | `01`–`09` 与 `99` 不得用作业务目录编号 |
| `00` 用法 | 仅工作区第一层的规范类目录可用 `00`（如 `00-Specs`）；其余层级的目录不得使用 `00` |
| 描述段 | 非空，规则与 §4 描述段一致，长度上限同为 60 字符 |
| 扩展名 | 目录名不得带扩展名；句点不在描述段字符集内 |
| 层级一致性 | 任意层级均按本文法校验，上级目录不改变下一层的形态要求 |

编号由定名人按号段选定，规则只约束编号位数与保留号，不做自动分配。

| 目录名示例 | 判定 | 原因 |
| --- | --- | --- |
| `10-Projects` | 合规 | 编号 10 可用，描述段字符合规 |
| `00-Specs` | 合规 | 工作区第一层规范类目录，`00` 号段对其放行 |
| `99-Archives` | 保留号 | `99` 只用于归档区自身，不作为新建业务目录 |
| `00-Temp` | 不合规 | `00` 仅限第一层规范类目录 |
| `Projects` | 不合规 | 缺少两位编号 |
| `10- 开头空格` | 不合规 | 描述段以空格开头 |

## 3 文件名结构

文件名由必填描述段与三个可选尾段构成，解析自右向左，尾段识别只发生在完整名称的末尾。

```text
<描述>[-v<整数>.<整数>][-YYYYMMDD][.<扩展名>]
```

解析按固定六步执行：

1. **切分扩展名**：按最后一个句点切分；当剩余段数不少于 3、且倒数第二段与末段均以字母开头并只含小写字母与数字时，两段合并为扩展名（`tar.gz`、`d.ts`），否则只取末段。
2. **多段版本识别**：尾部出现 `-v` 加三段及以上数字（如 `-v1.0.0`）时判为违规并截断该段。
3. **日期识别**：尾部 `-` 加 8 位数字识别为日期段。
4. **版本识别**：尾部 `-v<整数>.<整数>` 识别为版本段，任一段有前导零即判违规。
5. **括号日期兜底**：未识别到尾部日期时，尾部 `(<8 位数字>)` 视为日期段。
6. **描述段归属**：剩余部分整体为描述段。

## 4 逐段规则

描述段是唯一必填段，其余三段出现即须合法；各项判定互不替代，任一不通过即整名拒绝。

| 段 | 规则 |
| --- | --- |
| 描述段 | 1–60 字符（按 Unicode 码点计，不含版本、日期与扩展名）；不得以空格或句点开头或结尾；不得含句点 |
| 描述段字符集 | 中日韩统一表意文字基本区 `U+4E00–U+9FFF`、扩展 A `U+3400–U+4DBF`、ASCII 字母与数字、半角空格、下划线 `_`、连字符 `-`、半角括号 `()`、全角括号 `（）`；未列字符一律拒绝 |
| 版本段 | `v<整数>.<整数>`，恰两段十进制、无前导零；位于日期段之前、完整扩展名之前 |
| 版本递增 | 谱系为同目录、同描述、同扩展名；同谱系新版本数值必须大于现存最大版本 |
| 日期段 | `YYYYMMDD`，8 位且为真实公历日期，`20260230` 一类不存在的日期拒绝 |
| 扩展名 | 只含小写字母与数字，最多两段；复合扩展名整体保留 |
| 保留名 | 禁用 `CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`；按第一个句点之前的基名、大小写不敏感判定 |
| 重名 | 同一目录下名称经 NFC 归一化再大小写折叠后相同即判重名，禁止以大小写或 Unicode 变体共存 |

被字符集拒绝的典型字符包括 emoji、`$`、`[`、`]`、`{`、`}`、冒号、顿号、问号与全角空格。

## 5 顺序与识别约定

版本段与日期段只在尾部被识别，错序不触发报错，只会改变语义归属；定名时须按固定顺序书写。

1. **顺序固定**：正确形态为 `描述-版本-日期-扩展名`。写成 `报告-20261022-v1.2.docx` 时版本被识别、日期被并入描述段，名称仍算合规但日期语义丢失。
2. **括号日期只认 8 位纯数字**：`(20260230)` 按日期校验并被拒绝；`(AI image)`、`(86页)` 等非 8 位纯数字归入描述段，不参与日期识别。
3. **版本段只认尾部**：`report-v1.2-extra.docx` 中 `-v1.2` 不在尾部，整串进入描述段，版本不被识别。
4. **版本最多两段**：`-v1.0.0` 判为违规。
5. **扩展名区分大小写**：`.PDF` 不合规，`.pdf` 合规。
6. **点前缀不参与判定**：`.`、`..` 之外以点开头的名称（如 `.DS_Store`）不按本规则判形态。

## 6 合规与不合规示例

示例覆盖四个尾段的组合与常见失误。

| 名称 | 判定 | 原因 |
| --- | --- | --- |
| `季度报告-v1.2-20261022.docx` | 合规 | 描述、版本、日期、扩展名齐备且顺序正确 |
| `Meme - EU Canada US Flags (AI image).png` | 合规 | 空格、连字符、括号均在描述段字符集内 |
| `notes (86页).txt` | 合规 | 括号内容非 8 位纯数字，属描述段 |
| `archive.tar.gz` | 合规 | 复合扩展名整体保留 |
| `report-v1.0.0.docx` | 不合规 | 版本三段 |
| `report-v01.2.docx` | 不合规 | 版本有前导零 |
| `notes (20260230).txt` | 不合规 | 日期不存在 |
| `report.PDF` | 不合规 | 扩展名须小写 |
| `dollar$.txt`、`emoji😀.txt` | 不合规 | 字符集外字符 |
| `con.txt`、`COM1.docx` | 不合规 | Windows 保留名 |

## 7 归档改名

归档不改变文件内容，只在名称末端插入日期标记；归档副本的路径与原名对应，归档区内部结构不参与 §2 至 §5 的判定。

| 对象 | 结果 |
| --- | --- |
| 普通文件 | 扩展名前插日期戳：`report-v1.0.docx` → `report-v1.0-ARCHIVED-20261023.docx` |
| 目录、单段点前缀文件 | 不拆扩展名，整名追加：`.DS_Store` → `.DS_Store-ARCHIVED-20261029`，`.venv` → `.venv-ARCHIVED-20261029` |
| 项目整体归档目录 | 保留原名、不插日期；目标名称已被占用时退化为 `<名>-ARCHIVED-YYYYMMDD` |
| 同日冲突 | 仅清理类与项目整体归档在退化命名后递增 `-2`、`-3`；其余场合目标已存在即停止，不覆盖 |
| 还原 | 摘除 `-ARCHIVED-YYYYMMDD` 及 `-<序号>` 标记后移回原名，原名已被占用即停止 |

## 8 命名执行要求

命名是写入的前置条件，判定与改名过程须留痕，不得静默处理。

- 新建对象的名称须一次生成合规，禁止先落盘再改名。
- 名称不合规即停止，不自动删除字符、不自动截断、不自动替换。
- 改名须单条提交并经确认后执行，禁止批量盲改。
- 同一目录下已存在折叠后相同的名称时，改用新的描述段，不得靠大小写或 Unicode 变体区分。
- 版本升级产生的新文件须使用更大的版本号，旧版本按 §7 归档。

## 9 定名自查清单

- [ ] 目录名为 `两位编号-描述`，编号非 `01`–`09`、`99`，`00` 仅用于第一层规范类目录
- [ ] 目录名不含句点与扩展名
- [ ] 文件名为 `描述[-vM.m][-YYYYMMDD][.ext]`，尾段顺序正确
- [ ] 描述段 1–60 字符，首尾非空格或句点，全部字符在字符集内
- [ ] 版本段两段十进制、无前导零，且数值大于同谱系现有最大版本
- [ ] 日期段为 8 位真实公历日期
- [ ] 扩展名小写，最多两段
- [ ] 名称未使用 Windows 保留名
- [ ] 同目录下不存在 NFC 归一化与大小写折叠后相同的名称
