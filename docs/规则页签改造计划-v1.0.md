# 规则页签改造计划 · v1.0

> **一句话定位**：把侧栏卡片的「目录」页签升级为「规则」页签，用一个页面承载路由规则、扫描排除与默认落点三块配置，两组配置可分别折叠。
>
> **版本与证据口径**：v1.0 · 2026-11-17 · 证据取自 `packages/maid` 5.0.0 源码（行号以本版文件为准）、`.maid/` 运行状态与同日界面截图。折叠功能为同日增补，记于附录 B。

## 1 现状：页签名已经名不副实

页签叫「目录」，但该页签承载的内容正在从单一目录表扩为整份规则集，卡片投影还与文件不同步。

### 1.1 页签与数据来源

页签值固定为 `dirs`、`misplaced`、`scan` 三个，标签取自文案键 `view.dirs`（中文 `src/client.js#L172`，英文 `src/client.js#L360`），页签声明在 `src/client.js#L2744-L2746`。目录区标题行把标签与条目数拼在一起，渲染为「目录 7」（`src/client.js#L3051`）。

### 1.2 投影过期

`.maid/status.json` 的生成时间为 2026-11-17T07:58，记录 `catalog.hash` 为 `sha256:77309564…`、目录 7 项；而 `.maid/catalog.yml` 的现行内容为 16:35 写入、`sha256:5d158ead…`、目录 8 项。卡片读的是投影，因此界面仍显示 7 项，`50-Works` 不出现。

投影只在保存、扫描、复核等动作触发时重算。手工编辑配置文件不会触发重算，卡片与文件因此长期处于不一致状态，且界面没有任何过期提示。

### 1.3 命名与内容的落差

合并扫描排除之后，页签内将同时出现两类完全不同的条目：目录路由（散文，写给模型）与扫描排除（精确名字，写给扫描器）。继续用「目录」作为页签名，会让第二类内容无处安放，也会让人误以为整页只与目录有关。

**结论**：页面需要重命名与分区，投影需要一条随文件变化而重算的路径，二者同批处理。

## 2 目标信息架构

一个页签、三个区域：路由规则在上，扫描排除居中，默认落点在页脚一行，前两区各自可折叠。

### 2.1 版面（默认态）

│  ▸ 规则          ⚠ 日志          ≈ 扫描          │

│    ▾ 00-Specs                              日志   │
│       收什么：工作区通用规范文件，按交付载体分册…    │
│       不收：日志                     编辑   删除  │
│    ▸ 20-Learning                             —    │
│    ▸ 30-Media                                —    │

扫描排除折叠时只保留标题行与计数；标题行前置三角，点击整行切换。

### 2.2 展开态

```text
│  ▾ 扫描排除 11 项                          编辑    │
│    逐字匹配目录名，命中的目录整支跳过数据统计      │
│    〔 .git 〕〔 node_modules 〕〔 .venv 〕〔 … 〕   │
│    地板不可移除：.maid  .git                      │
```

三角方向表示当前状态：`▾` 已展开，`▸` 已折叠；目录行与区标题行使用同一种符号，缩进区分层级。

### 2.3 三区的职责

| 区域 | 内容来源 | 交互 | 默认态 | 空值表现 |
| --- | --- | --- | --- | --- |
| 路由规则 | `catalog.dirs` | 展开行、编辑、删除、切换默认、折叠 | 展开 | 空态引导新建 |
| 扫描排除 | `catalog.ignore` | 折叠、只读展示、切换到多行编辑、保存 | 折叠 | 只显示地板两条 |
| 默认落点 | `catalog.rootDefault` | 只读一行，修改入口在行内星标 | 常显 | 必然有值，无空态 |

### 2.4 术语表

| 位置 | 中文 | 英文 |
| --- | --- | --- |
| 页签 | 规则 | Rules |
| 区标题一 | 路由规则 | Routing |
| 区标题二 | 扫描排除 | Scan excludes |

| 地板行 | 地板不可移除 | Fixed floor, cannot be removed |

### 2.5 四条设计裁决

| 编号 | 项目 | 采用值 | 备选与差异 |
| --- | --- | --- | --- |
| D4 | 页签计数 | 只计目录数，扫描排除数放在该区标题内 | 备选为「8 目录 · 11 忽略」，代价是窄卡片下一行放不下 |
| D5 | 默认落点 | 维持页脚一行加行内星标，不独立成区 | 备选为独立区域，代价是与目录行的星标形成两处重复入口 |
| D6 | 默认折叠态 | 路由规则展开、扫描排除折叠 | 备选为两组都展开，代价是卡片高度多出约四行 |
| D7 | 编辑态与折叠 | 扫描排除处于编辑态时禁止折叠，须先保存或取消 | 备选为折叠即丢弃输入，代价是误触丢草稿 |

**结论**：页签语义收敛为「规则集」，两类配置各有明确位置且可独立折叠，页脚承担兜底说明。

## 3 交互契约

扫描排除区默认折叠，展开后默认只读；两组折叠状态各自记忆。

### 3.1 路由规则区

沿用现有交互：点击行首三角展开，展开后显示「收什么」「不收」两个标签与编辑、删除按钮（参考 `src/client.js#L1782-L1910`）。行尾第三列显示 `excludes` 摘要，空串显示破折号，默认落点行尾显示星标。

### 3.2 扫描排除区

| 状态 | 表现 | 触发 |
| --- | --- | --- |
| 只读 | 条目渲染为标签，一行内自动换行 | 默认（展开后） |
| 编辑 | 多行文本框，每行一个名字，行数随内容增长 | 点「编辑」 |
| 校验失败 | 行内红字指出含路径分隔符、空项或超长项，不发请求 | 点「保存」时 |
| 已保存 | 回到只读，标签重排 | 保存成功 |
| 只读会话 | 「编辑」按钮禁用并说明原因 | 会话为只读时 |

地板两条以只读标签形式固定显示在编辑区下方，不进入文本框，不参与去重判断。

### 3.3 折叠契约

| 项 | 取值 |
| --- | --- |
| 粒度 | 两区各自独立，互不影响 |
| 点击目标 | 整行区标题；区内「＋ 新建」「编辑」按钮阻止冒泡，点击不触发展开或折叠 |
| 折叠后表现 | 保留区名与计数，副标题、条目、地板行与区级按钮一并隐藏 |
| 键盘 | 标题行渲染为原生 `button`，Enter 与 Space 切换，`aria-expanded` 与 `aria-controls` 同步 |
| 持久化 | `localStorage` 键 `dsh-file-maid.section.<区名>`，值 `1` 为展开、`0` 为折叠 |
| 降级 | `localStorage` 不可用时按 D6 的默认态渲染，不报错 |
| 与编辑态互斥 | 扫描排除处于编辑态时标题行点击无效，`aria-disabled` 置真 |
| 焦点 | 切换后焦点留在标题按钮，不跳到列表 |

折叠状态的记忆沿用卡片现有的存储方式：`OPEN_KEY` 常量在 `src/client.js#L81`，读取在 `#L3573`，写入在 `#L3588`。新增键按同一形态命名，避免与卡片整体的折叠状态互相覆盖。

### 3.4 投影重算

页签打开时比较 `status.catalog.hash` 与当前文件内容摘要，不一致则先重算再渲染，避免出现 1.2 节那种「文件 8 项、界面 7 项」的状态。

**结论**：四类状态都有明确出口，编辑失败不会留下半保存状态，折叠不会撞上未保存的草稿。

## 5 与数据层计划的关系

本计划只承担视图与文案，数据层由《扫描排除合并计划 v1.0》承担，两者可分别发布但存在硬依赖。

| 场景 | 数据层已落地 | 数据层未落地 |
| --- | --- | --- |
| 扫描排除区 | 可编辑 | 只读展示，隐藏「编辑」按钮 |
| 折叠 | 正常 | 正常，折叠不依赖字段 |
| 投影重算 | 正常 | 仍可做，但字段不完整 |
| 页签改名 | 可独立发布 | 可独立发布 |

**结论**：页签改名、分区与折叠可先做，编辑能力等数据层就位后再开放。

## 8 风险与回退

风险集中在改名带来的文档不同步、窄卡片排版与折叠误触。

| 编号 | 风险 | 缓解 |
| --- | --- | --- |
| R1 | 改名后 `docs/ui-card-design.md` 与截图仍写「目录」 | 与代码同批更新该文档 |
| R2 | 窄卡片下扫描排除标签流式换行挤压高度 | 只读态最多显示两行，超出折叠为「还有 N 项」 |
| R3 | 编辑态与行内编辑同时展开时焦点争夺 | 任一编辑态打开时收起另一处 |
| R4 | 重算引入首次打开的额外延迟 | 只在哈希不一致时重算，一致时直接渲染 |
| R5 | 点「＋ 新建」时事件冒泡触发折叠，误收起正在编辑的列表 | 标题行内按钮统一 `stopPropagation`，并用 UI-88 锁定 |

回退按提交粒度 `git revert`；纯文案改动可单独回退而保留分区与折叠。

**结论**：五项风险都不涉及数据迁移，回退代价可控。

## 9 排障指引

四张卡片对应改名与折叠上线后最常见的异常。

| 症状 | 机制诱因 | 排查与处置 |
| --- | --- | --- |
| 页签仍显示「目录」 | 客户端 bundle 未更新 | 刷新页面；仍不变则查 `src/client.js#L172` 是否已改并重新构建 |
| 界面比文件少一项 | 投影未重算（页签打开路径未比对哈希） | 点「扫描」触发重算，或按 3.4 节补比较逻辑 |
| 折叠后刷新又展开 | `localStorage` 键名与卡片整体折叠键冲突或被清空 | 查 `dsh-file-maid.section.<区名>` 是否写入，确认未复用 `OPEN_KEY` |
| 扫描排除区没有编辑按钮 | 数据层未落地，视图按降级分支渲染 | 确认 `surfaces/manage.js#L27` 的白名单是否含 `ignore` |
