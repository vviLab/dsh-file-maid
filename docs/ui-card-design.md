# 文档妹抖侧栏卡片 · UI 设计记录

> **一句话定位**：记录 `dsh-file-maid` 在 DSH Web 侧栏呈现的卡片 UI，从落点选型、挂载机制到几何与状态表达的设计决定及其证据。
> **版本**：v1（2026-11-03，Asia/Shanghai）
> **证据口径**：代码证据标注 `[文件相对仓库根的路径#L起-L止]`；几何与像素数据来自浏览器运行时实测，测量方法见第 9 节；未取得运行时证据的判断在正文中标注「未验证」。

## 1 定位与设计边界

**导语**：这张卡片的职责是让使用者在一个侧栏区域内看到受控根的路由状态、切换工作区根、翻阅目录与错投记录。

- 使用者：正在 DSH Web 里整理文件的人。卡片不承担配置编辑，`catalog.yml` 仍由人直接写。
- 数据来源：受控根下的 `.maid/status.json` 快照，由宿主侧插件在每次扫描后原子写入。
- 呈现约束：侧栏面板宽 272px，卡片可用宽 264px；同一列里上方是分段页签（任务／频道／定时），下方是工作区与会话列表。
- 不承担：批量归档、文件内容预览、路由规则编辑。

**结论**：卡片是只读投影 + 三个入口（切根、刷新、翻阅），任何写操作都留在工具层，避免在 264px 宽的空间里做二次确认。

## 2 落点选型

**导语**：侧栏没有可直接插入「工作区之上、页签之下」的槽位，最终落点由三次否决与一次机制改造共同确定。

| 候选落点 | 否决证据 | 结论 |
| --- | --- | --- |
| `conversation.composer.dock` | 与模型名、费用、上下文百分比同排，属输入区语义 | 否决 |
| `conversation.view` 页签 | 页签栏已满，入口落到「更多会话视图」菜单内，可发现性差 | 否决 |
| `sidebar.panellist` 图标 | 264px 宽下图标行只容纳 7 个，第 8 个被裁切，会挤掉内置项 | 否决 |
| `sidebar.footer.action` | 组件确实渲染，但当前皮肤未绘制该座位 | 否决 |
| 包装 `sidebar.workspaces` 的 occupant | 位置正确，但切会话时页面主线程卡死（见第 3 节） | 否决 |
| 自建挂载点 + 独立 React root | 见第 3 节，实测三次会话切换无异常 | **采用** |

`sidebar` 槽位本身是 single 且已被占用，其子座位全集为 `sidebar.panellist.actions`、`sidebar.footer.action`、`sidebar.panellist`、`sidebar.brand.mark`、`sidebar.toggle.badge`、`sidebar.settings`、`sidebar.workspaces`、`sidebar.brand.name`；分段页签行不是槽位，只能通过占用 `sidebar.workspaces` 的组件上的 `__dshNativeTabs` 注册表插入，而该注册表无法承载「独立一行」。

**结论**：落点约束的本质是「一个不属于任何槽位的行位」，因此实现选择绕开槽位系统，改为在浏览区容器内自建子节点。

## 3 挂载机制

**导语**：卡片在 `#dsh-st-shell-panel` 内自建 `[data-file-maid="cardslot"]` 子节点，用独立 React root 渲染，浏览区组件不被本插件重新渲染。

挂载序列 `[packages/maid/src/client.js#L1258-L1338]`：

1. 定位容器：`document.querySelector('#dsh-st-shell-panel')`，失败时退回 `.bhn1Oq_root` 的父元素 `[packages/maid/src/client.js#L1276]`。
2. 建节点与 root：`host.setAttribute('data-file-maid','cardslot')` + `reactDom.createRoot(host).render(h(FileMaidCard))` `[packages/maid/src/client.js#L1286]`。
3. 改容器方向：容器加 `data-file-maid-panel`，样式将其置为纵向排列并把卡片置为 `flex:0 0 auto` `[packages/maid/src/client.js#L506-L510]`。
4. 兜底重插：`MutationObserver` 只观察 `document.body` 的 `childList`，用一次 microtask 合并整批变更后查一次容器，容器被重建时把节点重新 prepend；`settle()` 一旦判定成功即断开观察，避免「卡片已挂上、兜底图标又被注册」的双入口 `[packages/maid/src/client.js#L1387-L1480]`。
5. 失败回退：容器在 3 秒（24 × 125 ms）内仍未出现、或宿主没有 `react-dom/client` 时，注册 `sidebar.panellist` 图标。宽版 `main` 面板仍为无条件注册，其在「卡片挂载成功」时不可达，取舍见 §7。

被否决方案（包装 occupant）的失败机制：包装后由本插件调用 `h(original, props)` 重新渲染另一个插件的组件，会话切换时该组件持有的 context 已销毁，抛出 `cannot get required service "remote" in inactive context`；`dsh-automation` 的错误边界捕获后页面主线程持续忙，CDP 的 `Page.navigate`、`Page.captureScreenshot`、`Runtime.evaluate` 全部超时十分钟以上。临时移除包装逻辑后同一操作不再卡死，责任至此定位。

**结论**：跨插件 UI 的组合只应发生在 DOM 层（插入兄弟节点），不应发生在 React 树层（替换 occupant 组件），否则宿主组件的生命周期不再由它自己的注册方掌控。

## 4 布局与几何

**导语**：卡片固定占侧栏的 8–272px 区间，收起 32px（与侧栏页签行同高）、展开 129px（该值量于仍有根行时；2026-11-04 移走根行后未重测）。卡片头只放判定与操作，不放装饰：折叠箭头、标题、状态徽标、刷新按钮，四者瓜分 30px 行宽。

结构自上而下：卡片头、分段控件、正文；未启用时没有正文，以置灰页签收尾。工作区名字不占行——它作为后缀接在卡片头标题后面（`文档妹抖 · Work`）。

```
┌ ▾ 文档妹抖 · Work  ● 未启用        [刷新] ┐   卡片头 30px（含上下描边共 32px）
│ [目录]  [错投]  [扫描]                            │   分段控件（悬停≈「工作区 Work」；未启用时置灰）
└──────────────────────────────────────────────────┘
```

关键几何（实测，方法见第 9 节）：

| 元素 | 左 | 右 | 宽 | 高 |
| --- | --- | --- | --- | --- |
| 侧栏浏览区容器 | 8 | 280 | 272 | — |
| 分段页签行（任务／频道／定时） | 8 | 272 | 264 | 32 |
| 卡片（收起） | 8 | 272 | 264 | 32 |
| 卡片（展开，未初始化态） | 8 | 272 | 264 | 129 |
| 分段控件轨道 | 8 | 272 | 264 | 34 |
| 分段控件页签 | — | — | — | 28 |

右边界对齐由挂载点的 `padding-right: var(--dsh-sidebar-inline-padding,12px)` 实现 `[packages/maid/src/client.js#L509]`，与页签行共用同一变量，换皮肤时跟随。

**结论**：卡片与页签行共享同一左右边界而非贴齐列边，是侧栏内「同一层级元素」的唯一可判定标准。

> 2026-11-04 起嵌入态正文首行新增一句状态说明（§5），展开高度不再是固定值，随文案行数变化；上表 129 px 为未初始化态旧测值，本版未重测。

> 2026-11-05 起分段控件在卡片正文内固定：正文照旧由 `cardbody` 限高并滚动，控件行粘在滚动口顶端（条带 38 px，按宿主控件的轨道内边距算出，见 §15.1），列表在其下方通过。滚动后可读区为 `min(46vh,320px) − 38px`；未滚动时条带本来就在首屏顶部，占用不变。机制、选型与代价见 §15.1。

## 5 状态表达

**导语**：状态由「同色圆点 + 同色调文字」表达，同一句解释同时出现在正文首行与悬停气泡里，两者都不是唯一入口。

- 四种色调：`ok`（已启用）、`warn`（未启用、暂无数据、降级）、`error`（配置有问题、读不到数据）、`muted`（已关闭）`[packages/maid/src/client.js#L676-L688]`。
- 圆点 6px、外圈 18% 同色光晕；徽标是 `[data-file-maid="badge"][data-tone="ok|warn|error|muted"]`，四态把色值写进 `--maid-tone`；文字取 58% 状态色与主体文字色混合，亮色主题下对比度由此从 3.74–3.94:1 提到 4.5:1 以上。
- 徽标文字单行省略（`badgelabel`），不再撑破卡片头；图标色与文字色同源，避免「圆点有语义、文字看不清」。
- 解释文案由面板经 `publishCardState({tone,label,detail,refresh})` 发布给卡片头 `[packages/maid/src/client.js#L798-L806]`。
- 悬停气泡用 `createPortal` 渲染到 `document.body`，按触发元素 `getBoundingClientRect()` 定位并对视口夹取；距视口底边不足 96 px 时翻到徽标上方，滚动或缩放时关闭 `[packages/maid/src/client.js#L1218-L1288]`。
- 嵌入态正文可渲染一句 `hint`，但它只补徽标说不出的部分：下一步、后果（`不再归类或拦截新文件。`）或解析器原话（`catalogState === 'ERROR'` 时直接用第一条 error message）。徽标已经说清的状态（读取中、已关闭、暂无数据、**未启用**）不渲染任何 `hint`，正文留空而不是复述一遍——未启用态的解法（整理一次文件）放进了徽标的悬停说明，不占正文一行。2026-11-05 起这句说明只有一个外壳：页签不可用时它渲染成「目录表／说明」两行空态（仍是同一句话），页签可用时移到目录页正文内，与另两页的空态同形（§15.2）。
- 同一句只出现一次：有 `hint` 时空态槽与横幅都不再重复它。
- 分段控件在 `catalogState !== 'MANAGED'`（或快照未就绪）时保持位置但置灰不可用：外层 `[data-file-maid="viewslot"][data-disabled="true"]` 降到 45% 不透明度、`pointer-events:none`、`aria-disabled`，兜底按钮同时带原生 `disabled`。此时卡片不渲染空正文，只留「工作区 → 说明 → 置灰页签」三段；宽版页仍保留正文槽，因为那里的说明文字在横幅里。
- 文案面向使用者，不面向实现：不出现 `catalog.yml`、`maid_route`、`maid_scan`、`opt-out` 等文件名或工具名，也不解释内部的三选一流程；每条不超过一句，且**不复述徽标已经说过的词**——徽标给状态，`hint` 给动作（例：徽标`未启用` + `让 AI 整理一次文件会自动开启。`）。
- 宽版页保留横幅：读取失败与 `ERROR` 各一条 `[data-file-maid="banner"][data-tone="error|warn"]`，降级横幅带文件数与耗时，两种形态共用。

选择 portal 而非原生 `title` 的原因：徽标位于卡片头 `<button>` 内，按钮自身的 `title` 优先，且卡片与侧栏容器的 `overflow` 会裁切原生提示。

**结论**：状态辨识依赖颜色与圆点，语义解释依赖悬停；两者分离后，卡片正文可去掉整块横幅而不丢失信息。

## 5.1 降级提示

宿主进入 `degraded` 时全扫范围收窄为受管目录并集，受管区之外的新文件不再被发现。卡片为此显示一条横幅：

| 项 | 规则 |
| --- | --- |
| 文案 | `文件太多，只跟踪受管目录；区外新文件不会被发现。`——说后果，不说 `degraded`、不说预算常量 |
| 数字 | 进 `title`：`扫描 11109 个文件用了 334 毫秒`；不进正文 |
| 关闭 | 右上角 `×`（`bannerclose`），点击后按根记入 `localStorage`（`dsh-file-maid.degraded.dismissed`），本次降级不再打扰 |
| 复位 | 扫描重新落入预算后自动清除该记录，下一次超预算会照常提示；重启或刷新不会让旧提示复活 |
| 不可关闭的部分 | 徽标仍是 warn 色，`stateDetail` 仍是同一句后果——关闭只收起横幅，不改变状态 |

`degraded` 在宿主侧是黏性的：只有 `catalog.yml` 哈希变化才会置回 `false`（`applyCatalog`）。所以「关闭」只处理打扰，不处理根因；降级的根因仍要靠减少文件数或调整预算。

## 6 数据与根跟随

**导语**：卡片不接收槽位 props，直接订阅会话服务；工作区根跟随中间栏当前会话。

- 会话列表：`ctx.sessions.list`（SnapshotStore），`useSessionServiceList()` 在 `useEffect` 内 `subscribe` 并在回调里 `getSnapshot()`。
- 插件上下文：`apply(ctx)` 的 `ctx` 不在模块作用域，模块级 `services` 保存引用后供卡片读取。
- 根跟随：`activeCwdOf(list)` 取 `retainedBy.mainView > 0` 且 `updatedAt` 最大那行的 `cwd` `[packages/maid/src/client.js#L372-L380]`；手动选择过根后，`activeCwd` 变化即清空手动值以恢复跟随。
- 选择权只给宽版页：卡片挂在一个会话的侧栏里，若就地允许换根，正文显示的就是另一个工作区，而卡片看起来仍在描述当前会话。卡片不带下拉。
- 卡片不占一行来说工作区：名字作为后缀接在标题后（`[data-file-maid="cardsuffix"]`，` · Work`，取 `folderName(root)`，整段 `title` 给全路径）。
- 截断的优先级写在样式里：`[data-file-maid="cardtitle"]{flex:0 0 auto}` 让「文档妹抖」永不收缩，后缀 `{flex:0 8 auto;max-width:76px;text-overflow:ellipsis}` 先让路。理由是标题被截成「文档…」比看不全工作区名更糟。
- 页签标签仍带同一句 `title`（`cardTitle`），作为后缀省略号的补充；页签置灰时 `pointer-events` 只关内部 `[role="tab"]`，外层 `[data-file-maid="viewslot"]` 仍接得住悬停。
- 宽版页仍保留一行（`[data-file-maid="rootline"]` = `rootlabel` 工作区 + `rootvalue` 目录名，整行 `title` 给全路径）：那里有横向空间，也有多根选择器。
- 显示的是**目录名**而不是缩短后的路径：`…/Desktop/Work` 这类前缀省略后再截断，读起来像一串路标，且等宽字体会让它更像个技术字段。
- 首帧：会话快照未到达时状态置为 `loading`，不显示「没有根」。

**结论**：根跟随的判据是侧栏自己判断「画在中间栏」所用的同一字段，因此切换工作区的视觉结果与卡片选根结果一致。

## 7 交互

**导语**：卡片只有三个交互：折叠、刷新、切换根；折叠状态跨刷新保留。

| 交互 | 触发 | 行为 | 持久化 |
| --- | --- | --- | --- |
| 折叠／展开 | 点击卡片头左侧的 `cardtoggle` 按钮 | 正文显隐，箭头旋转 90°；`aria-expanded` 与 `aria-controls="file-maid-cardbody"` 同步 | `localStorage['dsh-file-maid.card.open']` `[packages/maid/src/client.js#L73]` |
| 刷新 | 卡片头右侧按钮（折叠按钮的兄弟节点） | 重新拉取 `status.json`，不影响展开态 | 不持久化 |
| 切换根 | 只在宽版页出现 | 切换后清空目录展开态；卡片内无此控件 | 不持久化，随当前会话根重置 |

折叠时正文保持挂载（`hidden` + `display:none`），因此收起态仍显示状态徽标。卡片头是容器 `div`，折叠与刷新是两个并列的按钮：早先把整行做成一个按钮并在其中嵌入刷新按钮，点刷新会同时触发折叠，且嵌套按钮在 HTML 里非法。

**结论**：所有交互都不写插件状态文件，卡片在只读会话下与普通会话表现一致。

**待定**：宽版 `main` 面板在卡片挂载成功的会话里没有入口，两条处置路线（删除宽版，或把兜底图标常驻侧栏）属于产品取舍，本版未擅自选择。

## 8 排障指引

**导语**：三组症状分别对应挂载、样式与提示的已知诱因。

| 症状 | 机制诱因 | 排查步骤 |
| --- | --- | --- |
| 侧栏看不到卡片 | 容器 `#dsh-st-shell-panel` 未出现，或宿主无 `react-dom/client`，走回退路径注册图标 | 查 `[data-file-maid="cardslot"]` 是否存在；无则查 `sidebar.panellist` 是否有本插件图标 |
| 改样式后界面无变化 | 浏览器按带 `rev` 的模块 URL 缓存 bundle，`Page.reload({ignoreCache:true})` 仍可能命中旧模块 | 先 `Network.clearBrowserCache` 再 reload；用 `getComputedStyle` 读新规则是否生效 |
| 悬停徽标不出现提示 | 使用原生 `title` 时被按钮 `title` 抢占，或气泡被容器 `overflow` 裁切 | 查 `document.body` 下是否存在 `[data-file-maid="statetipbox"]`；确认走的是 `StateTip` 路径 |
| 分段控件文字与图标不居中 | 用 `!important` 压缩了 `SegmentedTabs` 的高度与字号，内部滑块度量与页签不一致 | 只按比例同缩页签、字号、图标；轨道高度由页签高度决定 |
| 切会话后页面卡死 | 曾以包装 occupant 的方式组合 UI，切换后重新渲染了他人组件 | 确认卡片走独立挂载点；控制台不应出现 `cannot get required service "remote" in inactive context` |

**结论**：三组诱因都属于「组合方式」问题而非样式问题，排查应从 DOM 结构与模块缓存入手，而不是逐条试 CSS。

## 9 验证方法

**导语**：几何与对齐用运行时像素测量判定，不用截图目测。

1. 几何：`getBoundingClientRect()` 取容器、页签行、卡片、轨道、页签的矩形，比对左右边界与中心。
2. 对齐：`Page.captureScreenshot` 带 `clip` 与 `scale:10` 抓局部，用像素统计每行亮点数得到图标与文字的墨迹上下边界，换算成 CSS 像素中心后求差。
3. 生效性：改样式后先 `Network.enable` → `Network.clearBrowserCache` → `Page.reload({ignoreCache:true})`，再用 `getComputedStyle` 确认新声明存在。
4. 截图仅在像素数据与预期不符时用于定位区域。
5. 静态契约：`test/ui.test.js` 的 `UI-07` 在没有浏览器的情况下锁住两件靠肉眼才发现的事——CSS 里出现的每个 `[data-file-maid="x"]` 都必须有渲染路径生产它，且不得再用 `^=`／`*=` 之类的前缀或子串匹配。

**结论**：盒模型中心相同不代表视觉居中，判定依据必须是墨迹边界而非元素矩形。

## 10 初始化入口（历史原型，端点已移除）

卡片此前是纯只读投影：它经 `workspaceFiles` 读 `status.json`，从不请求宿主做任何决定。三个 `maid_init` 答案只有模型能选，于是未初始化的根在界面上没有入口——徽标说「未启用」，页签置灰，然后就没有下一步了。

本节记录补这条入口时选的路，以及它的边界。**当前状态：原型，未在真机验证过。**

### 10.1 为什么不用现成的那几条路

| 候选 | 结论 |
| --- | --- |
| 卡片里加一行「在对话里说：整理一次文件」 | 最短，但仍要把人赶回对话框，且刚因为重复被删过一次 |
| 往输入框写一句提示词 | 需要宿主暴露写 composer 的 API，未确认存在 |
| 插件自己暴露一个 Client 可调用的端点 | 采用 |

### 10.2 端点怎么接

三处都只有结构性校验，没有「是否由 `@deepseek-ai/dsh-typert-generator` 生成」的检查，所以一个 `link:` 装载、无构建步骤的插件也能接入：

| 环节 | 实现 | 依据 |
| --- | --- | --- |
| 宿主注册 | `ctx.typert.register({ package:'dsh-file-maid', face:'host', schemas:[], model:{…}, invocations:[descriptor] })` | `dsh-typert-registry/lib/index.js:463`；`validateInvocation`（`:584`）只校验命名与 codec 结构 |
| 宿主服务 | `ctx.provide('fileMaid', service)`，服务对象自带 `typertRemote = { service: 自己, serviceKey:'fileMaid', namespace:'fileMaid' }` | 派发前 `validateBinding`（`dsh-api-gateway/lib/index.js:1729`）要求接收者自身带该绑定 |
| 客户端挂载 | `ctx.remote.$mount({ package:'dsh-file-maid', descriptors:[descriptor] })` | `dsh-api-gateway/lib/client.browser.js:1669`；`validateContribution`（`:1718`）只查重名与命名冲突 |
| 输入 codec | `{ mode:'strict', typeSymbol:'string', create:()=>({parse}) }` | `requireStrictCodec`（`:2107`）要求 strict；不引入 zod |
| 结果 codec | `{ mode:'src-json' }` | `validateCodec`（`dsh-typert-registry/lib/index.js:624`）直接放行 |
| 权限门禁 | 无新增 action | `dsh-api-gateway/lib/index.js:1207` 只对非 owner peer 调 `remoteAccess.decide`；本机 GUI 是 owner |

### 10.3 端点不重写初始化

`fileMaid/init` 收 `root`，只用它**选中**哪一个活根，写入目标取自该根 entry 里那个 agent 自己的 `session.header.cwd`；查不到 entry 就直接拒绝，所以调用方无法凭空指定一个宿主没在服务的路径。随后重入 `maid_init` 工具：

```js
const envelope = await tools.get('maid_init').execute({ mode: 'init' }, { name: 'maid_init', agent });
```

借已有 agent 而不是新造一个，是因为 `roots.acquire()` 会加引用计数：一个新对象永远不会被 `release()`，那个根从此不回收（`entryOfRoot` 就是为此新增的只读查找）。重入同一份工具实现，也让只读会话拒绝、`.maid/opt-out` 守护、`root_default` 推断、审计与随后的扫描都不需要第二份代码。

### 10.4 边界

- 只暴露 `init`。`defer` 与 `opt_out` 仍只有模型能选；`root_default` 也不能由界面指定。
- 按钮只在 `catalogState === 'UNINITIALIZED'` 时有会话可指时出现；宿主没有 `typert` 或没有注册该端点时，客户端挂载失败于 `console.debug`，卡片回到只读，不弹错。
- 客户端是 classic script，无法 `import` 宿主模块，因此 `INIT_DESCRIPTOR` 是 `initDescriptor()` 的字面量副本；`UI-09` 断言两份逐字段一致，漂移在用例里失败而不是在调用时。
- 宿主侧改动不热加载：**必须重启 `dsh web` 才会出现按钮**。
- 接收者按**位置**取参：Gateway 用 `Reflect.apply(method, receiver, args)`（`dsh-api-gateway/lib/index.js:952`）派发，一个参数就是 `init(root)`，不是 `init({ root })`。按信封对象写会在服务里读到 `undefined`，表现成「参数永远是空的」——这一处曾连续两次把错误指向别处。
- 注册必须等 `typert` 就绪：插件按装载顺序 apply，一次性 `ctx.get('typert')` 读到 `undefined` 时端点就没注册，而客户端仍会挂载成功，调用于是表现为 `transport failure for /api/fileMaid/init: HTTP 404`（实测）。改用 `ctx.inject(['typert'], …)` 在服务就绪后注册；服务本身 `provide` 在插件自己的 fiber 上——Gateway 从根向上解析接收者，挂在子 fiber 上的服务父级看不见。

## 11 初始化问询端点

卡片不再重入 `maid_init`，改用三个专用端点；模型侧只保留 `defer` 与 `opt_out`，`interview`／`init` 一律返回 `E_MAID_CARD_REQUIRED`。

| 端点 | 入参 | 作用 |
| --- | --- | --- |
| `fileMaid/form` | `root`, `sessionId` | 只读：形态（空／脏／已初始化／broken／opted-out）、候选、被丢弃的登记行、根级散文件、当前目录表 |
| `fileMaid/preview` | `root`, `sessionId`, `kind`, `payload` | 校验 `init`／`edit`／`optout`，返回差异与一次性凭证 |
| `fileMaid/apply` | `root`, `sessionId`, `interviewId` | 消费凭证落盘：反覆盖闸门 → 建目录 → 写表 → 首扫 |

凭证 32 位十六进制、10 分钟、单次有效，绑定载荷哈希与预览时的 `catalog.yml` 哈希；基线不一致回 `E_MAID_STALE`。写入权限按卡片所选会话的 `sessionId` 判定，只读会话回 `E_MAID_READONLY`，不静默降级。`apply` 期间置 `entry.applying`，`fs.watch` 的目录表事件直接丢弃，避免与自身首扫竞态。

卡片侧：三种形态共用一张表单；已初始化形态用同一张表单做增、改、删与「停止管理」；`broken` 与 `opted-out` 只渲染刷新。

## 12 卡片分层与首屏（2026-11-04）

卡片把三种寿命不同的对象拆成两层：浏览层常驻，编辑层独占正文，诊断信息折叠。

| 层 | 内容 | 进入 |
| --- | --- | --- |
| 浏览 | 目录分节头「目录 N + 编辑」、前 5 行 + 「还有 N 个」、三段页签；未受管时另有一行「开始设置」。默认落点行带 `★ 默认落点` 文字标签，不另加装饰 | 默认 |
| 编辑 | 初始化表单、目录增删改、预览确认、停止管理 | 浏览行的「开始设置」／台账分节头的「编辑」 |
| 诊断 | 扫描三组事实（§14）、长错误 | 页签内或宽版页 |

编辑层由 `editMode` 五态驱动：`none`、`init`、`catalog`、`preview`、`stop`；激活时浏览层整体不渲染，`viewslot` 与 `bodyBlock` 保持相邻。

问询表单**按需取**：浏览层只读 `status.json` 投影，挂载时不调 `fileMaid/form`。进入编辑层（`openEdit`）才置 `formWanted`，表单到达后停留在编辑层，不再把操作者弹回浏览层。由此，未受管根的浏览层只给一个入口按钮，位置在**分段页签下方、水平居中**——先由页签说明这个根将来能提供什么，再由按钮说明现在能做什么。它站在投影上（`state.phase === 'absent'` 或 `catalogState === 'UNINITIALIZED'`），不预览尚未取到的模板摘要；卡片的受管根仍用台账分节头的「编辑」，宽版页没有分节头，改由同一入口提供「编辑目录表」。

`form` 失败时按 Host 的稳定 code 给下一步：`E_MAID_NO_ROOT` → 「这个工作区没有正在运行的会话；打开一个会话后再试。」，`E_MAID_NO_SESSION` → 「选中的会话已经关闭；刷新后重试。」，原码只写进 `title` 供排障。失败只出现在编辑层，浏览层不再出现红字。在途请求用递增序号（`formRun`）判新旧，**不用副作用自身的 cleanup 作废**——把 `form.phase` 放进依赖后，置 `loading` 会重跑副作用并触发 cleanup，结果把正在等待的那份回包扔掉，卡片停在「正在读取…」不再前进（实测）。

目录名后直接跟角色标签（`受管` / `自管`，10px 弱化色）。展开详情收敛为两行上限：有错投时一行 `错投 N`，末尾恒有一行 `关键词 a · b · c`；行右侧的文件数已够判断占用，卡片不再复述体积。宽版页表格保留「体积」列，那里有列宽承载它。不再重复角色，也不再用胶囊标签堆叠。

目录编辑行渲染的是「合并视图」：把 `ops` 应用到目录表后再显示。被改的行显示 `受管 → 自管`，被标记移除的行加删除线并标注「待移除」，新增行标「待写入」；每行展开提供切换角色、移除与撤销。移除只是标记，真正落盘发生在预览确认后。`ops` 非空时返回按钮改为「放弃 N 项修改」，需二次点击；`ops` 为空且落点未变时「预览改动」禁用并显示「无改动」。

## 14 扫描页签的分组（2026-11-05）

**导语**：扫描页签原先把 `status.scan`、目录表判定参数与根路径平铺成 12 组键值。264px 的卡片正文装不下，工作区根与权重行各折成两行，布尔直出 `true` / `false`，末尾的指纹被裁断——使用者在配图上看到的是「一长列键值，正文溢出、末尾截断」。本节记录问题机制、重排后的三组式与判定依据。

改动前（同一 `scanBody`，本次已替换，原文为 `kv` 网格 + `k` / 值两列 × 12 行）：

| 现象 | 机制 |
| --- | --- |
| 12 行读不完 | 每行一组键值，`max-content` 标签列 + 值列，放大到 2 行后远超 `cardbody` 的 `min(46vh,320px)` |
| 工作区根折成两行 | 值单元格带 `overflowWrap:anywhere`，`/Users/…/Work` 在任意字符处断行，没有 `title` 可回看全路径 |
| 权重行折行 | `kw 1 · desc 1 · prior 0.5` 写成一串，`kw`／`desc`／`prior` 是配置键名，既占宽也不是读者语言 |
| `true` / `false` 直出 | 布尔值未本地化，与同页「观察中」这类人话值并排出现 |
| 指纹被截断 | `sha256:` + 64 位十六进制放不进值列，尾部被 `overflow:hidden` 裁掉，且无 `title` |
| 结论排在设置之后 | 「是否新鲜、是否降级」在第 3、9 行，读者要先略过判定参数才看得到「这次扫描是否正常」 |

改动后（渲染 `[packages/maid/src/client.js#L1463-L1585]`，样式 `#L890-L911`，路径缩短 `#L657-L663`）：


| 决定 | 依据 |
| --- | --- |
| 三组：本次扫描 / 判定参数 / 根与基线 | 三组各答一个问题（这次扫到了什么、用什么规则判定、绑在哪个根与哪版目录表）；12 行平铺时这三类混在一起，读者无法按用途收拢视线 |
| 计数三格独占一行（13px/600 数字 + 10px 说明） | 文件数、目录数、耗时是同一句话的三个量，并排读比纵向逐行读快；三格等宽（实测各 74px），数字与说明各自成列 |
| 其余每个值右对齐成一条轴（`scanval`：`margin-left:auto` + `text-align:right` + `tabular-nums`） | 8 行值的右边缘落在同一像素（264px 容器实测 253px），竖扫时不必逐行重读标签；标签同为 2 个汉字，左边缘也自然成轴 |
| 组头是 10.5px/600 次要色小标，不是 11.5px 主色分节头 | 组头只负责分组，答案在下面的数字与状态词；用主色分节头会让三个标题与 13px 的数字争夺第一眼。层级仍由字号承担（10.5 / 11 / 13），不新增字重档 |
| 每组带 `role="group"` 与 `aria-label`（取组头文字） | 组头只是视觉小标，读屏拿不到「这一串值属于本次扫描还是判定参数」；补上分组语义不增加任何可见行 |
| 布尔本地化为词汇：「正常」/「已降级」、「有快照」/「无快照」、「观察中」/「未观察」 | 卡片其余部分一律给人话；`true` / `false` 属于实现枚举，与「观察中」并排时读者要先翻译 |
| 降级为真时值取 `--dsw-alias-state-warn-primary` | 唯一需要看一眼的异常；其余值保持文字色，避免三个组里出现多套强调 |
| 计数走 `toLocaleString('en-US')` 千分位 | `11109` 需要数位，`11,109` 不需要；`en-US` 固定，不因宿主 locale 变化而让卡片宽度抖动 |
| 根路径只保留末两段并加 `…/` 前缀，全路径进 `title` | 卡片正文只有 252px；尾部省略会保留 `/Users/…` 这类无人阅读的前缀而切掉真正的叶名，改为舍前缀留叶名后一行放得下 `…/Desktop/Work`，需要全路径时悬停可见 |
| 指纹取 `sha256:` 之后 12 位，全值进 `title` | 12 位十六进制足以区分两版目录表，且在 10.5px 等宽下不折行；完整摘要留在 `title`，排障时照样可复制核对 |
| 删掉「状态」行 | 状态已是卡片头与宽版页头部的徽标，扫描页复述一遍既占行又与徽标抢位置（第 5 节「徽标说状态、说明只说下一步」） |
| 权重写成「关键词 2 · 用途 1 · 先验 0.5」 | `kw`／`desc`／`prior` 是 `catalog.yml` 的键名；`用途` 与初始化页 `init.purpose` 用词一致，读者不必先学配置名 |
| 宽版页把该块限宽 340px | 与错投列表同理：1080px 下三格数字会被拉成广告牌，340px 约合卡片正文宽度，两处读起来是同一个组件 |
| 组间距 7px、组内 1px、行高 1.45 | 分组靠「组间一段空、组内贴紧」表达，比给每组建框更安静；行高 1.45 让 11px 的值与 10.5px 的标签共基线 |

高度核对：在 264px 宽、`46vh` 上限 283.82px 的容器里，正文内容（含分段页签行）为 279px，不出现滚动；视口高 600px 时上限 276px，仅最后一行的下缘露出约 3px。首屏始终先给「本次扫描」的三个数与时间、降级状态，判定参数与基线在其后。

## 15 固定页签与三页布局语言的收敛（2026-11-05）

**导语**：分段页签（目录／错投／扫描）原先排在滚动容器内部，卡片正文一滚就跟着走出视野，滚到列表中部时既看不到当前页签也换不了页；三个页签又各写一套分节头、行高、对齐轴、字号色阶、空态与分隔，翻页时读者的眼睛要重新校准一次。本节记录两条改动的机制、选型与落地后的共同规则。

### 15.1 页签固定

改动前：`[data-file-maid="cardbody"]` 同时承担「限高 + 滚动」两件事（`max-height:min(46vh,320px)`、`overflow-y:auto`），而页签行 `viewslot` 是它的后代，于是滚动内容与控件一起移动。

改动后（`[packages/maid/src/client.js#L848]`）：

```css
[data-file-maid="card"] [data-file-maid="viewslot"]{position:sticky;top:0;z-index:2;padding:2px 0 4px;background:var(--dsw-alias-bg-layer-1);}
```

| 决策 | 依据 |
| --- | --- |
| 用 `position:sticky`，不把卡片拆成「固定头 + 滚动体」两段 | 拆段要给正文再包一层滚动容器：卡片内出现两个滚动口，滚轮与 `overscroll-behavior` 要在两处各判一次，行距也要为拼接处让出 1–2px。sticky 让 `cardbody` 继续做唯一的滚动口，DOM 树、渲染顺序与高度预算都不动，撤掉只需删一条规则 |
| 只对卡片生效（`[data-file-maid="card"] [data-file-maid="viewslot"]`），宽版页不固定 | 宽版页是整页文档滚动（`[data-file-maid="page"]` 自身 `overflow:auto`），`top:0` 会把页签钉到视口顶端、压在页面内容上，与本意相反。实测宽版页该元素仍为 `position:static` |
| 用不透明底色 `--dsw-alias-bg-layer-1` 覆盖滚过的行 | 粘住的瞬间行会从页签下方穿过，透明底会把行文字透到标签上；颜色取卡片自身的层色，主题切换时自动跟随 |
| `z-index:2`，不做新的一层 portal | 只需压过同级的行与分节头；卡片是独立的 React root，再开浮层会重演「浮层被卡片 `overflow:hidden` 裁切」的老问题 |
| 上下留 2px／4px 内边距，不加分隔线 | 分隔线在未滚动时也常驻，会与分段控件自带的轨道描边叠成两道；留白足以表达「文字到这里为止」 |
| 滚动口同时给 `scroll-padding-top:42px`（≥ 条带高度 38px，见下方算式） | 焦点把行滚进视野时（长列表里 Shift+Tab 往回走）浏览器会把该行贴到滚动口顶端，正好落在固定页签下面，看得见焦点框却看不见行。`scroll-padding-top` 让「滚进视野」停在页签下方，且不改变任何布局。取 42 而不是 38：宿主若把分段控件的轨道内边距从 2px 改回默认 4px，条带会变成 42px，上界值不必随宿主升级重算 |

代价（页签固定优先，「首开一屏读完」让位）：

- 条带高度按 CSS 算式为 38px：页签 28px（卡片对 `[role="tab"]` 的高度覆盖）+ 轨道内边距 2×2px（`--segmented-tabs-inset:2px`）+ 条带上下留白 2px／4px。宿主控件若按默认 4px 内边距渲染，则为 42px。
- 未滚动时什么都不损失：页签行本来就在首屏顶部，固定后占用不变。
- 一旦滚动，可读区从 320px 变成约 282px（320 − 38），约占去两行（22.67px）。目录页只给五行、本来不滚动，不受影响；错投页（十条两行记录，行高 39.38px）与扫描页（正文超过上限）都要滚动：前者可见条数由 8 条降到 7 条，后者可见行数少两行。
- 被页签覆盖的那 38px 上的行既不可见也不可点：滚动后要操作某一行，得先让它离开页签下方。这是固定页签的固有代价，不做例外；键盘焦点是唯一被专门照顾的情形（`scroll-padding-top`）。

静态渲染实测（264px 卡片宽、主题变量取近似值、`46vh` 上限落在 320px；读数来自前一轮，条带当时记为 42px。与本节按覆盖值算出的 38px 差 4px，推测是渲染时未带上 `--segmented-tabs-inset:2px`；两种取法都超过 320px 上限，滚动结论不变）：`position:sticky`、`top:0`、滚动 220px 后 `viewslot` 距滚动口顶端仍为 0（未滚动前也是 0），首行已移到 −148.3px 处即已进入页签下方；在滚动口顶端做命中测试命中的是页签而非行；宽版页同一元素为 `static`；错投正文 323px、扫描正文 338px（含页签条带）均超过 320px 上限，即两者确实会滚动。本轮无浏览器（本机 9222 无 CDP，`browser_*` 连不上宿主页面），条带高度改用 CSS 算式核对为 38px，未再做视觉复核。

### 15.2 三页共同规则

度量只在两个根上声明一次（`[packages/maid/src/client.js#L941]`），卡片与宽版页共用同一套：

```css
[data-file-maid="tabpage"],[data-file-maid="page"]{--maid-fs-row:11.5px;--maid-fs-meta:10.5px;--maid-row-pad:3px;--maid-gap-kv:8px;--maid-gap-section:7px;--maid-gap-head:2px;}
```

| 层 | 规则 | 落点 | 与改动前的差别 |
| --- | --- | --- | --- |
| 分节头 | 10.5px／600／次要色／字距 .3px，标签后可续条数，右侧最多一个动作，动作与头同字号 | `sectionhead`（`#L789`）；卡片三页、扫描页三组与宽版页目录页共用（宽版页在 `#L2256` 附近，空列表时不渲染头，交给空态说明） | 目录页与错投页原先是 11–11.5px 主色粗体，只有扫描组头是 10.5px 小标；宽版页目录页原是一行 12px 主色粗体的 `section`，与同页的错投头不一致；现在四处同为一档 |
| 节距 | 头与行之间 7px；组与组之间 7px；组内头与内容 2px | `viewbody`、`scanlayout`（`#L942`）、`scangroup` | 原先 8px／7px／1px 三种 |

扫描页新增空态：`status.scan` 缺失时不再渲染八行破折号，改为「没有扫描记录／这个工作区有会话在运行时，这里会出现最近一次扫描。」（`scan.empty`、`scan.emptyHint`，zh/en 各一份）。目录页的空态仍由状态链给出原因，只把外壳换成同一个块，因此「未启用」这类状态仍然不占正文（`hintText` 为空时不渲染）。

第 14 节「组头是 10.5px/600 次要色小标，不是 11.5px 主色分节头」的比较对象已随本次改动消失：主色分节头在三页上都不再存在，组头就是分节头本身。

**结论**：页签用一条作用域限定的 `position:sticky` 固定在卡片正文顶端，滚动容器仍是 `cardbody` 一个，代价是滚动后少看约两行；三页收敛为「一档分节头 + 一套行度量 + 一条右轴 + 一个两行空态」，度量以自定义属性声明在两个根上，卡片与宽版页不得单点漂移。新增与修改的规则全部使用 `--dsw-alias-*` 与既有半径，未新增 `!important`；钩子与规则仍由 `UI-07` 双向校验，固定页签由 `UI-29` 锁定，三页共同语言由 `UI-30` 锁定，宽版页沿用同一档分节头由 `UI-31` 锁定。数据来自把 `client.js` 样式规则抽到无头页面的静态渲染（主题变量近似、未接宿主真实样式）；本机 9222 无 CDP，真机截图未取得（未验证）。
