# 文档妹抖（dsh-file-maid）

DSH 插件。让 AI 保存文件时把它放进工作区里合适的文件夹，事后还能告诉你：这次存进来的文件，有几个没走它这条路。

## 它替你省掉什么

工作区分了十来个文件夹——规范、笔记、媒体、职务文档、输出物……你让 AI「把这次评审的结论整理成周报存下来」，它得自己猜放哪。猜错很常见：丢在根目录，或者一股脑塞进默认的 `80-Outputs`。三天后你要找，得翻四个文件夹。

装上之后，AI 不再自己拼路径，改成调用 `maid_put`，由插件按你写好的目录表决定落点。返回值会写明放到了哪、依据是什么——你自己指定的，还是回落到默认目录；`violations` 非空说明这个名字不能写，按提示改了重试即可。不满意就改目录表，不用每次在对话里提醒它。

它只决定「新文件放哪个目录」，不读也不改文件内容，不接管别的插件的界面。

## 安装

需要 DSH `>=0.2.2-alpha.2 <0.3.0`、Node.js 22 及以上；运行时只依赖一个包 `yaml`。

```bash
cd packages/maid
npm install --omit=dev          # link: 装插件时宿主不会替你装这个包的依赖
node scripts/check-manifest.js  # 自检清单、补丁与依赖引用
dsh plugin add link:$PWD
```

装完重启 `dsh web`——插件跑在宿主进程里，不重启不加载；只改卡片样式的话刷新页面即可。卸载：`dsh plugin remove dsh-file-maid`。

## 第一次用

打开会话区的「文档妹抖」页签，点「启用这个根」（向导标题是「初始化这个根」），它会读出工作区现有的文件夹，让你逐个登记，并给每个目录补一句「这里收什么」；也能自己手动加。加完目录才会生效，判断依据是 `<工作区>/.maid/catalog.yml` 存在。之后让 AI 存文件，照常说明用途即可；想先看看会放哪而不动手，让它调 `maid_route`。

## 五个工具

| 工具 | 干什么 | 写盘 |
| --- | --- | --- |
| `maid_put` | 存新文件：算落点、写进去、记一笔 | 会 |
| `maid_route` | 只回答「会放哪」，列出候选 | 不会 |
| `maid_review` | 列出上次扫描以来没记账的改动，带体积和变更时间 | 不会 |
| `maid_scan` | 数各目录文件、跟上次对比，可选出一份报告或一份 JSON 清单 | 只写报告 |
| `maid_init` | 只用于「暂不启用」或「这个目录不要管」 | 看情况 |

想知道「有哪些文件没走这条路」时用 `maid_review`，**不要用 `maid_scan`**：扫描会把基线往前推，看一眼就等于放弃追查；复核只测量，`index.json` 一动不动。

`maid_put` 返回里的 `decided_by` 说明落点是谁定的：`agent` 调用方指定、`default` 默认目录；`violations` 非空就按提示改。同名默认不覆盖，要覆盖得传 `overwrite: true`；指定的目录必须已在目录表里声明，没声明会被直接拒绝，不会悄悄回落到默认目录。

## 卡片三个页签

- **目录**：编辑目录表，可新建、修改、删除；路径可以用系统的文件夹对话框挑，在这里新增的路径必须是已存在的文件夹，插件不替你创建。展开任意一行点「编辑」，勾上「没指定目录时，文件放这里」，保存后就换成了它。这一行放的是判断不出来该去哪的文件——调用方没指定目录时，才会落到这里。这一行和最后一个目录不能删；删掉只是不再参与路由，磁盘上的文件不动。
- **日志**：分两组，各自按时间倒序、每页 10 条。上面是「没走妹抖的」（标着「自己进来的」，展开能看原因并跳到扫描页），下面是「妹抖安排的」，每条带依据，用来回答「刚才那个文件为什么去了那儿」。
- **扫描**：最上面一句话给结论——有没有文件没走这条路；下面三个数字（妹抖安排的 / 其他工具写的 / 没走妹抖的）加起来就是这段时间的新增，对不上时多一格「说不清」。结论行右侧是「在日志里看」和「重新扫一次」，最后一行可折叠地写着这次花了多久，也可以勾上「扫描时同时导出清单」。扫描按目录并发进行，并发上限跟着磁盘的实际响应速度自适应——本地盘跑满 8 路，网络盘或慢盘自动退回串行，所以换台机器也不用改配置。

没走妹抖的明细每页 5 条：点一行展开看完整路径、体积和变更时间，确认是自己干的就点「这条我知道」。已确认的收在下面「已确认 N 条」里，可以随时撤销。确认只影响清单的呈现，不动账目，也不会移动文件——下次扫描仍会把它算进净增，只是不再列出来。

页面背后调六个接口：`fileMaid/draft` 只校验一条待添加路径、`fileMaid/pick` 拉系统选目录框、`fileMaid/save` 增改删目录、`fileMaid/scan` 立刻扫描、`fileMaid/review` 取漏网清单（只测量）、`fileMaid/ack` 确认或撤销一条。

参考量级：四千个文件、六百多个目录的工作区，本机空闲时一次扫描约 20 毫秒（并发化之前约 38 毫秒）；与对话同时进行时 25–35 毫秒，差额来自事件循环排队，不是磁盘。需要把并发钉死时设环境变量 `FILE_MAID_SCAN_CONCURRENCY=1`（取值 1–8，设定后不再自适应），适合把工作区放在移动硬盘或网络盘上的情况。

## 配置

`<工作区>/.maid/catalog.yml` 是唯一需要人写的文件，也是唯一的路由依据：

```yaml
version: 1
root_default: 80-Outputs            # 判断不出来时放这里，必须同时出现在下面的 dirs 里
dirs:
  - { path: 00-Specs, purpose: 工作区通用规范文件, excludes: 日志 }
  - { path: 50-Works, purpose: 职务相关工作文档 }
  - { path: 80-Outputs, purpose: 非项目输出物的默认落点 }
```

`purpose` 和 `excludes` 都会出现在给模型看的目录表里，`purpose` 还参与候选排序，所以写清楚「收什么」比写漂亮重要。`root_default` 指的是哪个目录，那个目录必须先登记在 `dirs` 里。

旧版本还有一段 `rules:`（关键词 → 目录）的硬匹配。它在 2026-11 被撤掉了：路由该由模型判断，靠关键词命中的第二条判断链只会跟模型打架——两个都说得出理由，文件却落到了没人要的地方。老配置里保留这段不影响加载，插件会忽略它并给一条警告。

## `.maid` 目录里有什么

插件只往 `<工作区>/.maid/` 写东西，目录权限 `0700`、文件 `0600`，同机别的账号读不到：

| 文件 | 是什么 |
| --- | --- |
| `catalog.yml` | 上面的配置，人写 |
| `index.json` | 上次扫描的文件数基线，每次扫描覆盖 |
| `status.json` | 卡片的显示数据；删了只是卡片空一下，不影响路由 |
| `decisions.jsonl` | 每次存文件的落点与依据 |
| `writes.jsonl` | 每次经工具写文件的记录（`write` / `edit` / `apply_patch`） |
| `guard.jsonl` | 每次试图改 `.maid` 被拒的记录 |
| `audit.jsonl` | 目录表改动、确认操作与旧报告清理 |
| `acknowledged.json` | 确认过的漏网条目（`path@ctime`），读写时剪枝，留 90 天或 5,000 条 |

另有 `rotation.json`（每个日志最近一次滚动的时间）、`reports/`（扫描报告与 JSON 清单同茎成对，按对留 30 份、最多 90 天）和 `opt-out`（标记「这个工作区不要管」）。四个 `.jsonl` 各按 1 MB 滚动、保留 10 份；除这些以外，插件只写业务文件本身，以及 `maid_put` 需要时新建的目录。

## 它拦不住什么

最需要知道的一条：**它拦不住直接写文件。** 下载、导出、`bash` 重定向、`mv` / `cp`、别的插件或外部程序写进来的文件都不经过 `maid_put`，事前看不到，只能事后数：新增文件数 = 走插件的 + 工具写入的 + 两边都没记录的 + 对不上的。

- **走插件的**：`decisions.jsonl` 里有记录；
- **工具写入的**：`writes.jsonl` 里有记录；
- **两边都没记录的**：按文件 ctime（inode 变更时间）找出来的，`cp -p`、`rsync -a` 保留时间戳也躲不过；
- **对不上的**：新增里既没记账、也没被点名的部分。

这四个数是估算，用来看量级和趋势，不是精确核对：删除和移动会让数字下降，覆盖写不产生新增，目录间搬文件会同时改两个数。若某次扫描期间日志正好滚动过、或记录是从中途才开始有的，清单会留空、「对不上的」显示为空而不是 0——算不准时，插件宁可说不知道，也不报一个假的「一切正常」。

另外两点：它不能把已经发出的 `write` 改成 `maid_put`（宿主的拦截只有放行或拒绝，没有「换个目标」这个选项），所以做法是「给一条好走的路 + 事后核对」，不是「强制改道」；ctime 会把改名、`chmod`、`touch` 也算成候选，属于可接受的误报，两次扫描之间建了又删的文件看不到。
